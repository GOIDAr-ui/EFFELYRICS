# Проверка Windows 11 x64

## Подготовка

Установите официальное приложение Apple Music из Microsoft Store, войдите в собственный аккаунт и включите доступную вам композицию. Токены разработчика не нужны. Для проверки исходников установите Node.js 24 LTS и .NET SDK 10, выполните `npm ci`, `npm run bridge:build`, `npm run dev`. Для проверки дистрибутива — `npm run dist:win`, затем установщик и portable из `release/`.

## Чек-лист реальной интеграции (обязателен до заявления о совместимости)

- [ ] Windows 11 x64: installer устанавливается для текущего пользователя; portable запускается из каталога с пробелами и кириллицей. Нет требования отдельно установить .NET.
- [ ] Apple Music закрыта: приложение предлагает деморежим, не падает. Диагностика показывает отсутствие сессии.
- [ ] Открыть Apple Music, запустить трек: появилась выбранная Apple-сессия. Сравнить SourceAppUserModelId, заголовок, исполнителя, альбом и обложку с плеером.
- [ ] Проверить отсутствие обложки/альбома/названия: остальное приложение продолжает работать. Неизвестные title/artist заменяются UI-подписями.
- [ ] Play/Pause из Aurora реально управляет Apple Music, а обратное действие в Apple Music отражается в Aurora. Для каждой команды сравнить реальное поведение и capability в диагностике.
- [ ] Next/Previous переключают реальный трек, подсветка старого текста очищается.
- [ ] Открыть другое приложение с медиасессией: Aurora продолжает выбирать Apple Music, а не текущую системную сессию другого плеера.
- [ ] Свернуть/восстановить Apple Music; закрыть/снова открыть её: сессия теряется и обнаруживается повторно без перезапуска Aurora.
- [ ] Принудительно завершить мост: Aurora показывает недоступность команд, предлагает демо; перезапуск приложения восстанавливает мост.
- [ ] Сопоставить position/duration и возраст timeline в диагностике с Apple Music. Если позиция не передаётся, UI честно сообщает, что синхронизация недоступна.
- [ ] Импортировать собственный TTML с известными временными метками. Перематывать **в Apple Music** вперёд/назад, ставить паузу на слове, ждать 10 с, продолжать. Слово должно сразу соответствовать текущему времени, без накопления задержки.
- [ ] Проверить offset ±1 с; смену песни во время открытого диалога импорта; возврат к прежней песне и повторный импорт после перезапуска.
- [ ] Полноэкранный режим и выход, изменение размеров окна, масштаб экрана 100/150/200%, 60/120 Гц, системный Reduce Motion.
- [ ] Экономное качество не меняет выбор слова на той же позиции; фон меняется с обложкой без внешних запросов.
- [ ] Импорт неправильного XML, DTD, frame timing, файла >2 МБ показывает ошибку, оставляет приложение доступным.
- [ ] Закрытие Aurora завершает дочерний WindowsMediaBridge.exe; повторный запуск не оставляет прежние мосты.

## Демо без Apple Music

1. Выберите Деморежим и Воспроизвести. Слышать музыку не требуется: это тестовый таймер, не аудиоплеер.
2. Пауза на слове → подождать → слово не меняется.
3. Ползунок на 25.2 с → «Небо» активно без ожидания.
4. Возобновление продолжается от выбранной позиции, а не от прошедшего wall time.
5. Импортировать `examples/first-light.ttml`, перемотать на 0 с и 5 с.
6. Смена режима на Apple Music убирает демотекст. Диагностика всегда показывает Windows, даже в деморежиме.

## Статус проверки в облачной среде Linux

Прохождение unit tests, Playwright, JS-сборки, кросс-компиляции WinRT-моста и даже упаковки `.exe` **не является проверкой Apple Music**. Перечисленные ручные проверки требуют Windows 11. Включайте в отчёт версии Windows/Apple Music, ID выбранной сессии, доступные поля, capability и наблюдаемое поведение. Не прикладывайте токены или полные дампы среды.

Windows CI проверяет сборку и наличие обоих `.exe`/моста, но не запускает Apple Music, не входит в аккаунт и не проверяет DRM. Дистрибутивы v0.1 unsigned, автоматический update не реализован.
