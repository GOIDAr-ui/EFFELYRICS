# v0.1.2: системная перемотка

Причина: range был disabled для любого режима, кроме demo; обработчик менял только demoClock. IPC и WindowsMediaSessionAdapter не имели seek-команды. Поэтому ошибка возникала до Windows API, независимо от возможностей Apple Music.

Исправление в fix/aurora-lyrics-v0.1.2, без перехода к новой версии:

- Нативный range поддерживает click/drag, preview времени, клавиатуру и touch. При отпускании/потере фокуса отправляется один target; промежуточное перетаскивание не шлёт команды. Preview не меняет PlaybackClock и текст. Демо продолжает работать локально.
- Main валидирует sender, конечные неотрицательные секунды. Мост проверяет сессию, trackId, Controls.IsPlaybackPositionEnabled, длительность и диапазон (если Windows его предоставила).
- TryChangePlaybackPositionAsync получает `StartTime.Ticks + TimeSpan.FromSeconds(target).Ticks`: 10 000 000 тиков в секунде. Это отличается от относительных секунд UI. При отсутствии диапазона MaxSeekTime/MinSeekTime окончательное решение принимает API.
- false/exception/IPC timeout возвращаются как ошибка; true означает лишь принятие. SeekController ждёт до 5 с: trackId тот же, timeline.LastUpdatedTime новее исходного и фактическая позиция в пределах 1,5 с цели (учёт задержки опроса/воспроизведения). Если Windows не обновляет timestamp, подтверждения нет.
- По snapshot обновляются общие часы, строка, слово и fill. Никаких animationend или оптимистичного seek реальных часов. При отказе/timeout preview убирается, показывается реальная позиция. Быстрые новые запросы вытесняют ожидание старых; старые ответы не перезаписывают результат новых.
- Отсутствие capability сохраняется как unknown, false как no. Неизвестная/нулевая длительность, неподдерживаемый seek и старый preload отключают range, но шкала фактического времени продолжает работать.
- В диагностике: Seek supported, Requested position, Actual position, Seek command result и Last seek error. Разрешён только документированный WinRT API.

## Windows 11 / Apple Music — обязательная ручная проверка

1. `npm ci`, `npm run bridge:build`, `npm run dev` (либо новая сборка v0.1.2 из Actions).
2. Включить песню. Открыть диагностику и проверить Seek supported. Если no/unknown — убедиться, что ползунок отключён и причина видна. Не объявлять это программной ошибкой без capability.
3. При yes нажать середину шкалы, затем перетащить к началу/концу. Во время drag видно preview, текст остаётся на фактическом времени. После отпускания сравнить Actual position и результат confirmed с самим Apple Music.
4. Повторить на паузе, при воспроизведении, со сменой трека и несколькими быстрыми перемотками. Строка/слово/fill должны следовать последнему подтверждённому timeline.
5. Проверить отказ/потерю сессии/необновляющийся timeline. Нельзя показывать confirmed только из-за движения ползунка или ответа API true.

Автоматические проверки используют mock transport/preload. Они не доказывают поддержку перемотки конкретной версией Apple Music. Реальная проверка Windows в этой Linux-сессии не выполнена.

Проверки текущей сессии: lint, TypeScript, build — прошли; 48 unit-тестов; 5 Playwright-сценариев, включая click/drag/preview/подтверждённый snapshot/ошибку IPC/пересчёт текста; WinRT bridge — скомпилирован. Неподдерживаемый seek, нулевая длительность, отказ, отсутствие нового timeline, смена трека и быстрые запросы покрыты unit-тестами. Это результаты Linux/mock-проверок, не тест реальной Apple Music.
