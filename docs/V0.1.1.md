# v0.1.1 — автоматические тексты и заполнение букв

Ветка: fix/aurora-lyrics-v0.1.1. Композиция First Light сохранена. При новых метаданных запускается поиск, проверяются название/исполнитель/альбом и доступная длительность (допуск 3 с). Live/remix не удаляются из названий. Неоднозначные совпадения требуют выбора версии. Ручной импорт приоритетен и отменяет поиск. При смене трека отменяется предыдущий запрос; ответы старой песни не применяются.

Источники и проверенные публичные условия (11 ноября 2026):

- AMLL TTML DB: https://github.com/amll-dev/amll-ttml-db — README документирует metadata/raw-lyrics-index.jsonl и raw-lyrics/*.ttml. LICENSE — CC0 для самостоятельно созданных вкладов; внешние данные сохраняют условия исходного источника. Автоматическая массовая загрузка/распространение текстов с приложением не выполняется. Атрибуция источника видна в UI. Индекс загружается один раз за процесс, ограничен 30 МБ; файлы — 2 МБ. Абсолютные AMLL времена обрабатываются отдельным режимом, стандартный относительный импорт сохранён.
- LRCLIB: https://github.com/tranxuanthang/lrclib — README описывает бесплатный machine-friendly API. https://lrclib.net/docs недоступен в этой среде (403), актуальные условия долгосрочного кеширования текстов не подтверждены. Провайдер /api/search реализован, но его реальный ответ здесь не проверен. Принимается только enhanced LRC с явными границами слов и конечной меткой; обычный syncedLyrics с построчными метками не выдаётся за WORD.

Кеш текстов намеренно локальный **в памяти процесса**, до 50 результатов; он работает при потере сети после загрузки. Между перезапусками тексты не сохраняются: право на долговременное хранение каждого внешнего файла не подтверждено. Это ограничение v0.1.1; не заявляется постоянный offline-кеш. Никакие тексты сторонних песен не включены в репозиторий или дистрибутив. Одинаковые ошибки/отсутствие также кешируются в пределах сессии. В метаданных без точного названия/исполнителя поиск не выполняется.

Подсветка: исходный текст и aria-hidden слой с градиентной маской имеют одинаковые глифы. Fill вычисляется из (time-start)/(end-start), без CSS-таймеров; кадровый цикл меняет только CSS-переменные, React memo блокирует перерисовку всего документа при каждом кадре. Пауза/seek/offset используют общие часы. Reduce Motion переключает на спокойную дискретную подсветку. Деморежим — визуальный тест последовательного заполнения, без аудио.

Обложка: MIME определяется по сигнатуре PNG/JPEG/WebP, а не только по ContentType Windows; поток дочитывается целиком. IPC/CSP допускают только bounded data images. При отсутствии изображения показана нейтральная заглушка, а не демонстрационная обложка. Фактический сбой пользователя и его устранение требуют Windows-проверки, не подтверждены mock-тестами.

Проверка Windows 11:
1. npm ci; npm run bridge:build; npm run dev.
2. Apple Music → песня → убедиться, что источник WORD найден автоматически. Если NONE, проверить доступ raw.githubusercontent.com и lrclib.net, затем использовать TTML.
3. При нескольких версиях выбрать подходящую; проверить паузу, seek в обе стороны и offset.
4. Быстро менять треки во время поиска — старый текст не должен появляться.
5. В диагностике проверить источник/поиск/строки/слова/WORD-LINE-NONE/текущее слово/fill/offset/обложку.
6. Проверить обложку после смены песни и закрытия Apple Music; при отсутствии — нейтральная заглушка.
7. Демо: остановить ползунок внутри слова — частичное заполнение неподвижно; продолжить — свет движется слева направо.

Не подтверждены: реальные треки Apple Music, LRCLIB live API, работа исправленной обложки на Windows. Смысловые эффекты не добавлены. Предыдущие Windows-бинарники v0.1 не являются сборкой v0.1.1.

Результаты текущей сессии: lint, TypeScript, production build прошли; 41 unit-тест и 4 Playwright-сценария прошли. WinRT bridge кросс-компилирован. Один реально загруженный AMLL TTML разобран (17 строк, WORD), без включения текста в репозиторий. Это не проверка совпадения с аудио Apple Music. LRCLIB сеть и ручные Windows-сценарии не проверены.
