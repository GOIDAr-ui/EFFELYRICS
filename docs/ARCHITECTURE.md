# Архитектура Aurora Lyrics v0.1

## Процессы и доверие

```text
Windows GSMTC ⇄ WindowsMediaBridge.exe (.NET 10 / WinRT)
                         ⇅ NDJSON, inherited stdin/stdout
Electron main — WindowsMediaSessionAdapter
                         ⇅ фиксированные IPC-каналы
Sandboxed preload → React / Vite renderer
                         ↓ playback time
 PlaybackClock → LyricSyncEngine → LyricsRenderer
```

Electron main запускает единственный мост из фиксированного каталога, без shell и сетевого сервера. .NET вызывает документированный `GlobalSystemMediaTransportControlsSessionManager.RequestAsync()`. Из доступных сессий выбирается только Apple Music по SourceAppUserModelId (`AppleInc.AppleMusicWin_*`, либо `AppleMusic.exe`); другие плееры не выбираются автоматически. Диагностика показывает исходные идентификаторы. Если будущая версия Apple изменит AUMID, потребуется отдельное подтверждённое обновление фильтра.

Сессия опрашивается 4 раза в секунду. Смена метаданных отслеживается через MediaPropertiesChanged с резервным опросом раз в 5 секунд. SessionsChanged заставляет заново привязать сессию даже при прежнем AUMID. Обложка передаётся по stdio/IPC только при изменении и кэшируется на границах процессов. Позиция GSMTC привязана к LastUpdatedTime, к ней добавляется прошедшее время только при Playing. PlaybackRate учитывается; длительность и позиция могут отсутствовать. Поля метаданных и обложка необязательны. GSMTC не предоставляет каталоговый Apple Music ID: trackId — SHA-256 от SourceAppUserModelId, названия, исполнителя, альбома и номера трека. Полностью одинаковые или отсутствующие метаданные могут не позволить отличить две песни; это ограничение требует проверки на реальных сессиях. Закрытие сессии выключает команды, очищает метаданные и документ текста. Next/Previous/Toggle проверяют Controls и возвращаемое WinRT значение. Каждая команда имеет ID и timeout 5 с.

Main нормализует и ограничивает данные до передачи интерфейсу. Preload экспортирует только getSnapshot, onSnapshot (с отпиской), command, importTTML, fullscreen. Нет универсального invoke, доступа к файловой системе или запуска команд. Main проверяет sender и главный frame. Выбор файла — системный диалог; лимит до чтения 2 МБ. Renderer не получает путь файла. В браузерной версии File API используется только после явного выбора файла.

Electron: contextIsolation=true, nodeIntegration=false, sandbox=true, webSecurity=true. Новые окна, навигация, webview и разрешения запрещены. CSP ограничивает скрипты своим origin, обложки — своим origin/data images. Remote assets, Apple fonts и private APIs не используются. Dev URL фиксирован и разрешён только вне упакованного приложения. Обложки принимаются только в png/jpeg/webp data URL, а SVG/HTML/внешние URL отбрасываются.

## Независимость времени

`PlaybackClock` получает авторитетные снимки и интерполирует время монотонными часами performance.now. Пауза фиксирует позицию, resume меняет anchor, seek сразу меняет позицию. Новый trackId сбрасывает старое время. Отсутствующая реальная позиция не экстраполируется.

`LyricSyncEngine` — чистая функция выбора строки/слова по времени + offset, интервалы `[start,end)`. Частота кадров и окончание CSS-переходов на результат не влияют. Границы слов пересчитываются на каждом обновлении интерфейса (30/20 fps), новые слова не ждут окончания анимации предыдущих. Автопрокрутка вызывается только при смене активной строки; Reduce Motion убирает плавный переход. У документа с line timing подсвечивается вся строка.

`TTMLParser` разбирает ограниченный поднабор TTML с сохранением порядка mixed content и пробелов. Он не обрабатывает DTD и отклоняет неподдерживаемые временные форматы. `LyricsProvider` — интерфейс будущих источников; `ImportedLyricsProvider` сохраняет документ по trackId только в памяти. Асинхронный импорт сверяет поколение запроса, трек и режим перед применением: файл от старого трека не попадёт в новый. Закрытый/пустой документ не сохраняет подсветку прежней песни.

## Будущие эффекты

`src/effects/types.ts` задаёт SemanticAnalyzer, EffectRegistry, EffectDefinition, WordEffectAssignment, EffectTimeline, VisualEffectRenderer, EffectSettings и EffectTimelineStore. Назначение хранит wordId, origin manual/analyzer, confidence/context и настройки силы/скорости/длительности. Таймлайн привязан к trackId с revision. Интерфейс анализатора принимает полный текст, ru/en и AbortSignal: это место для контекстного локального анализа, а не словаря ключевых слов.

Canvas/WebGL renderer получит playback time и таймлайн, а не будет управлять часами текста. При смене трека вызывается reset; при закрытии dispose освобождает ресурсы. Редактор сможет перезаписывать автоматические назначения ручными и хранить данные через EffectTimelineStore. Сейчас реализаций этих интерфейсов нет. WindowMode/WidgetLayout подготавливают компактный режим и виджеты, но UI их не обещает.

## Ресурсы и ограничения

При паузе цикл кадров остановлен. Во время воспроизведения один requestAnimationFrame loop ограничен 30/20 fps и отменяется при смене режима/unmount. Нет setTimeout на каждое слово или очереди эффектов. Импорт до 2 МБ/10 тысяч строк; сложная виртуализация больших текстов не входит в v0.1. Canvas на 1×1 используется для среднего цвета обложки только при её смене; устаревшая загрузка не меняет палитру. Таймеры IPC очищаются на ответ/exit, event subscriptions удаляются. Предпочтения сохраняются в localStorage без токенов и путей.

Система не получает звук, поэтому не может независимо подтвердить точность таймлайна Apple Music. GSMTC иногда возвращает устаревшие поля — диагностическая панель показывает их возраст. Ручная настройка offset корректирует постоянное смещение, но не восстанавливает отсутствующий таймлайн.

Официальный API: https://learn.microsoft.com/uwp/api/windows.media.control.globalsystemmediatransportcontrolssessionmanager
